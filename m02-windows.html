2. Cuentas: usuario, Administrator y SYSTEM

SIDEl Security Identifier es el “DNI” de cada usuario o grupo, p. ej. S-1-5-21-…-500. El final 500 es siempre el Administrator integrado; S-1-5-18 es SYSTEM.

5. Privilegios y UAC

Además de grupos, Windows asigna privilegios concretos a las cuentas. Se ven con whoami /priv.

PrivilegioQué permite¿Peligroso?
SeImpersonatePrivilegeActuar en nombre de otro usuario que se conecte a ti. Lo tienen las cuentas de servicio (IIS, MSSQL)Sí: suele permitir llegar a SYSTEM
SeBackupPrivilegeLeer cualquier archivo “para hacer copias”Sí: permite copiar SAM/SYSTEM
SeDebugPrivilegeInspeccionar la memoria de cualquier procesoSí
SeShutdownPrivilegeApagar el equipoNo
UACUser Account Control: la ventanita “¿Quieres permitir que esta aplicación haga cambios?”. Aunque seas administrador, tus programas se ejecutan con permisos reducidos hasta que aceptas. Por eso a veces ves que eres admin pero no puedes hacer cosas de admin (“integridad media” frente a “alta”).

6. Registro, servicios y tareas programadas

El registroEs el gran “archivo de configuración” de Windows, organizado como carpetas (claves) con valores. HKLM = configuración de la máquina; HKCU = del usuario actual.
reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run   # programas al iniciar
sc qc NombreServicio          # configuración de un servicio (ruta, cuenta)
Get-Service | Where-Object Status -eq Running
schtasks /query /fo LIST /v   # tareas programadas (como cron)

Fácil Traduce de Linux a Windows

Escribe el equivalente en Windows de: cat notas.txt, ip a, ps aux.

Solución: type notas.txt (o Get-Content), ipconfig, tasklist (o Get-Process).

Has entrado como la cuenta del servidor web. ¿Qué te llama la atención?

Solución: SeImpersonatePrivilege activado. Es muy frecuente en cuentas de servicio y es una de las vías más típicas para llegar a SYSTEM (familia de técnicas “Potato”, módulo 11).

Reto ¿Dónde buscarías contraseñas?

Enumera 5 lugares de un Windows donde a menudo quedan contraseñas olvidadas.

Solución: (1) historial de PowerShell (PSReadLine), (2) archivos de instalación desatendida C:\Windows\Panther\Unattend.xml, (3) web.config de IIS, (4) scripts y archivos .txt/.ini/.config en carpetas de usuarios y C:\, (5) credenciales guardadas (cmdkey /list) y claves del registro de programas (p. ej. autologon en Winlogon).
