1. La idea central

El empleado con una llave de másEres un empleado normal, pero descubres que puedes usar una máquina del almacén que, por error, arranca con la tarjeta del director. No “hackeas” nada: aprovechas un permiso mal dado. Escalar privilegios en Linux es encontrar algo que se ejecuta como root pero que tú puedes influir o controlar.

2. Enumeración local

Primero a mano (entiendes lo que ves), luego con un script que no se te escape nada.

id; sudo -l                 # ¿soy de algún grupo interesante? ¿puedo usar sudo?
uname -a; cat /etc/os-release   # versión de kernel y distro
find / -perm -4000 -type f 2>/dev/null    # binarios SUID
getcap -r / 2>/dev/null     # capabilities
cat /etc/crontab; ls -la /etc/cron.*      # tareas programadas
ps aux | grep root          # qué corre como root
ss -tulpn                   # servicios internos (solo localhost)
ls -la /home/*; ls -la ~    # archivos de usuarios
cat ~/.bash_history; env    # historial y variables (credenciales)
find / -writable -type d 2>/dev/null       # dónde puedo escribir
Scripts de enumeraciónLinPEAS (el más completo), linux-smart-enumeration (lse.sh) y pspy (ve procesos que arrancan sin ser root, ideal para cron ocultos). Pásalos con un servidor web (módulo 8) y ejecútalos desde /tmp.

4. sudo mal configurado y GTFOBins

GTFOBinsWeb (gtfobins.github.io) que recopila cómo programas legítimos de Unix pueden “abusarse” para leer archivos, escribir o ejecutar una shell cuando se lanzan con privilegios (sudo, SUID, capabilities). Es tu primera parada tras un sudo -l.
La función ocultaMuchos programas tienen una opción para “ejecutar un comando” (los editores, find, awk, vim, less…). Si el programa corre como root, ese comando también. Es como descubrir que la fotocopiadora tiene un modo que abre la caja fuerte.

Ejemplo conceptual: si sudo -l dice que puedes ejecutar less como root, dentro de less existe la orden para abrir una shell, y esa shell será de root. GTFOBins te da la sintaxis exacta para cada binario. No memorices: entiende el patrón y consulta la web.

Flujo1) sudo -l → 2) anota cada binario permitido → 3) búscalo en GTFOBins → 4) sigue la receta “Sudo”. Si no aparece, piensa si ese binario puede leer o sobrescribir un archivo clave (p. ej. /etc/passwd o /etc/shadow).

5. SUID y capabilities

Repaso del módulo 1: un binario SUID (-rwsr-xr-x) se ejecuta con los permisos de su dueño (normalmente root).

  1. Lista los SUID: find / -perm -4000 -type f 2>/dev/null.
  2. Compara con una lista de SUID “normales” (passwd, sudo, mount…). Lo que sobre es sospechoso.
  3. Busca el binario raro en GTFOBins (sección “SUID”).
  4. Si es un binario propio del sistema (ej. un programa a medida), revisa qué hace: ¿llama a otro programa sin ruta absoluta? ¿lee un archivo que tú controlas?
CapabilitiesPermisos finos que dan a un binario “trocitos” de los poderes de root sin ser SUID completo. getcap -r / 2>/dev/null. Por ejemplo, un binario con cap_setuid puede cambiarse a root. También están en GTFOBins.

6. Tareas cron y rutas escribibles

Si root ejecuta un script cada pocos minutos y tú puedes modificar ese script (o un archivo que use), le añades tus instrucciones y esperas a que se ejecute como root.

VarianteQué buscar
Script editableEl .sh del cron tiene permisos de escritura para tu usuario/grupo
Wildcard injectionEl cron usa comodines (*) sobre archivos que tú puedes crear (p. ej. tar *)
PATH relativoEl script llama a un comando sin ruta y tú puedes poner uno falso antes en el PATH
pspyMuchos cron no aparecen en /etc/crontab (están en el crontab de root). pspy te deja ver procesos que arrancan en tiempo real sin ser root: así descubres el cron oculto.

7. Kernel y servicios internos

  • Kernel: uname -r → busca exploits para esa versión (p. ej. familias conocidas). Úsalo como último recurso: puede colgar la máquina.
  • Servicios internos: ss -tulpn muestra servicios que solo escuchan en 127.0.0.1 (una base de datos, un panel). A veces corren como root y tienen credenciales débiles. Para alcanzarlos desde tu Kali necesitarás túneles (módulo 13).
  • Grupos: si estás en docker, lxd o disk, hay técnicas conocidas para leer el disco o montar un contenedor privilegiado y salir como root.

Fácil Primer vistazo

Acabas de entrar como www-data. Escribe los 3 comandos que ejecutarías primero.

Solución: id, sudo -l, uname -a. Luego SUID y cron. (No hay una única respuesta, pero estos tres dan muchísima información rápida.)

Media Interpreta sudo -l 
User bob may run the following commands on web01:
    (root) NOPASSWD: /usr/bin/vim /etc/apache2/sites-enabled/000.conf

¿Es explotable?

Solución: Sí. vim permite ejecutar comandos del sistema desde su interfaz, y aquí corre como root. Al editar ese archivo con vim como root, puedes lanzar una shell de root desde dentro del editor (receta exacta en GTFOBins → vim → Sudo). Mitigación: no dar sudo sobre editores; usar sudoedit con restricciones.

Media SUID sospechoso 
-rwsr-xr-x 1 root root 1.1M /usr/bin/find
-rwsr-xr-x 1 root root  27K /usr/bin/passwd

¿Cuál investigarías?

Solución: find. passwd con SUID es normal (necesita escribir en shadow). find con SUID no es habitual y en GTFOBins tiene una receta para ejecutar comandos como el dueño (root). Lo buscarías ahí.

Reto Cron oculto

/etc/crontab no muestra nada útil, pero sospechas que root ejecuta algo cada minuto. ¿Cómo lo confirmas y qué buscarías después?

Solución: ejecutas pspy y observas los procesos que arrancan periódicamente como UID 0. Si ves que root ejecuta, p. ej., /opt/scripts/backup.sh, compruebas sus permisos con ls -l. Si puedes escribir en ese archivo (o en un directorio que use con comodines), añades tus instrucciones y, al siguiente ciclo, se ejecutarán como root. Siempre: captura de pantalla de pspy y del antes/después para el reporte.
