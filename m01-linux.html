1. La terminal

Hablar con el ordenadorLa interfaz gráfica es como pedir en un restaurante señalando fotos del menú. La terminal es hablar directamente con el cocinero: más rápido, más preciso y puedes pedir cosas que no salen en el menú.

Casi todos los comandos siguen el patrón comando -opciones argumentos. Para pedir ayuda: man comando o comando --help.

2. El sistema de archivos

En Linux todo cuelga de una única raíz: /. No hay “C:”, “D:”.

RutasAbsoluta: empieza por / (/home/ana/notas.txt). Relativa: desde donde estás (notas.txt). Atajos: ~ = tu carpeta personal, . = aquí, .. = carpeta de arriba.

4. Usuarios, grupos y /etc/passwd

Cada persona o servicio tiene un usuario con un número (UID). root siempre es UID 0. Los usuarios se agrupan en grupos para compartir permisos.

root:x:0:0:root:/root:/bin/bash
ana:x:1000:1000:Ana Garcia:/home/ana:/bin/bash
www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
  • /etc/passwd: lista de usuarios. Todos pueden leerlo.
  • /etc/shadow: los hashes de las contraseñas. Solo root puede leerlo. Si un atacante lo lee, puede intentar crackearlos (módulo 9).
  • /etc/group: los grupos. Grupos “interesantes”: sudo, adm (lee logs), docker, lxd (módulo 10).
whoami          # ¿quién soy?
id              # mi UID, GID y grupos
sudo -l         # ¿qué puedo ejecutar como root con sudo?
su ana          # cambiar al usuario ana (pide su contraseña)

Permisos especiales: SUID

SUIDUn programa con el bit SUID (aparece una s en lugar de la x del dueño: -rwsr-xr-x) se ejecuta con los permisos de su dueño, no con los de quien lo lanza. Ejemplo legítimo: passwd, que necesita escribir en /etc/shadow.
La llave maestra prestadaSUID es como si el conserje te dejara usar su llave maestra solo para abrir el cuarto de la lavadora. Si la “lavadora” (el programa) permite hacer otras cosas, podrías acabar abriendo todo el edificio. Por eso, en el módulo 10 buscaremos programas SUID mal elegidos.
find / -perm -4000 -type f 2>/dev/null    # lista programas con SUID

Prácticas

Dónde practicarEl juego OverTheWire: Bandit (gratis, por SSH) es el mejor ejercicio de Linux para principiantes. Haz al menos hasta el nivel 20.
Fácil Calcula permisos

¿Qué número corresponde a rw-r-----? ¿Y qué letras son 755?

Solución: rw- = 6, r-- = 4, --- = 0 → 640. 755 = rwxr-xr-x.

Fácil Lee /etc/passwd

Dada la línea backup:x:0:0::/var/backups:/bin/bash, ¿qué tiene de raro?

Solución: Su UID es 0: este usuario es en realidad root con otro nombre. Es un hallazgo grave (puerta trasera o mala configuración).

Media Cuenta usuarios con shell

Escribe una sola línea que muestre solo los nombres de usuarios cuya shell termina en sh.

grep 'sh$' /etc/passwd | cut -d: -f1

grep 'sh$' filtra las líneas que acaban en “sh”; cut se queda con el primer campo.

Media Buscar credenciales olvidadas

Busca, sin mostrar errores, todos los archivos .php dentro de /var/www que contengan la palabra “password”, mostrando solo el nombre del archivo.

grep -ril "password" /var/www --include="*.php" 2>/dev/null

-r recursivo, -i sin distinguir mayúsculas, -l solo nombres de archivo.

Reto Interpreta este listado 
-rwsr-xr-x 1 root root  54K /usr/bin/passwd
-rwxrwxrwx 1 root root  120 /opt/backup.sh
-rw-r--r-- 1 root root  2.3K /etc/crontab   (contiene: */5 * * * * root /opt/backup.sh)

¿Qué ves de peligroso?

Solución: passwd con SUID es normal. Lo grave es que /opt/backup.sh tiene permisos 777 (cualquiera puede modificarlo) y root lo ejecuta cada 5 minutos desde cron. Cualquier usuario podría añadir instrucciones que se ejecutarían como root. Es una escalada de privilegios clásica que verás en el módulo 10. Mitigación: chmod 700 y que el dueño sea root.
