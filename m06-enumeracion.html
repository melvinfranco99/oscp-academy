1. Nmap paso a paso

NmapEl escáner de red más usado del mundo. Envía paquetes a un equipo y, según cómo responde, deduce qué puertos están abiertos, qué servicio hay detrás y su versión.
Llamar a todas las puertasNmap recorre un edificio llamando a cada puerta (puerto). Si alguien contesta, le pregunta “¿quién eres y qué versión?”. Con los scripts (-sC) además le hace unas cuantas preguntas típicas.

La estrategia en dos fases

  1. Fase rápida: descubrir todos los puertos TCP abiertos (hay 65.535). 
    nmap -p- --min-rate 2000 -Pn -oN todos.nmap 192.168.50.101
  2. Fase detallada: solo sobre los abiertos, versiones y scripts por defecto. 
    nmap -p 22,80,445 -sC -sV -Pn -oN detalle.nmap 192.168.50.101
  3. UDP (lento, solo los más comunes): 
    sudo nmap -sU --top-ports 50 -Pn -oN udp.nmap 192.168.50.101
OpciónQué hace
-p-Todos los puertos (1–65535). Sin ella, solo los 1000 más comunes
-p 22,80Solo esos puertos
-sSEscaneo SYN (“medio abierto”), por defecto con sudo. Rápido
-sTConexión TCP completa (sin sudo o a través de túneles)
-sUEscaneo UDP
-sVDetecta servicio y versión
-sCLanza los scripts NSE por defecto (seguros)
-OIntenta adivinar el sistema operativo
-PnNo hace ping previo (trata el equipo como vivo). Útil con Windows
-snSolo descubre equipos vivos, sin escanear puertos
--min-ratePaquetes por segundo mínimos (más rápido)
-oN / -oAGuarda la salida (normal / todos los formatos). Guarda siempre
--script vulnScripts que buscan vulnerabilidades conocidas

4. Enumeración web

whatweb http://192.168.50.101                       # tecnologías detectadas
curl -I http://192.168.50.101                       # solo cabeceras
curl http://192.168.50.101/robots.txt
gobuster dir -u http://192.168.50.101 -w /usr/share/wordlists/dirb/common.txt -x php,txt,bak

5. De la versión a la vulnerabilidad

  1. Anota el producto y la versión exacta: “vsftpd 2.3.4”.
  2. Busca en local: searchsploit vsftpd 2.3.4 (base de datos de Exploit-DB).
  3. Busca en Google: “vsftpd 2.3.4 exploit”, “… CVE”, “… github”.
  4. Lee el aviso: ¿afecta exactamente a tu versión? ¿requiere autenticación? ¿qué consigue?
  5. Lee el código del exploit (módulo 4) y pruébalo en tu lab.
No todo es CVEEn el OSCP muchas máquinas no se resuelven con un exploit, sino con malas configuraciones: credenciales por defecto, archivos con contraseñas, servicios con permisos de escritura… Si no encuentras un CVE, no te obsesiones.
Herramientas restringidasEn el examen no se permiten escáneres automáticos de vulnerabilidades comerciales (Nessus, OpenVAS…) ni explotación automática tipo sqlmap. Nmap con NSE, gobuster/ffuf, etc. sí. Consulta la lista vigente en la guía oficial.

Prácticas

Fácil Elige las opciones

Escribe el comando nmap que escanea todos los puertos TCP de 10.10.10.5 sin hacer ping, y guarda el resultado en full.nmap.

nmap -p- -Pn -oN full.nmap 10.10.10.5
Media Interpreta 
80/tcp   open  http     Microsoft IIS httpd 10.0
1433/tcp open  ms-sql-s Microsoft SQL Server 2019
3389/tcp open  ms-wbt-server
5985/tcp open  http     Microsoft HTTPAPI httpd 2.0

¿Qué sistema es y qué harías primero?

Solución: Un Windows Server con IIS, SQL Server, RDP y WinRM. Empezaría por la web (directorios, tecnología, formularios) y, si aparece alguna credencial, la probaría en MSSQL, RDP y WinRM. Si consigues ejecutar código como la cuenta de IIS o MSSQL, revisa whoami /priv (SeImpersonate).

Media Gobuster con extensiones

Busca en http://10.10.10.5 archivos .php y .bak con la wordlist common.txt.

gobuster dir -u http://10.10.10.5 -w /usr/share/wordlists/dirb/common.txt -x php,bak
