Escalada de privilegios en Windows

Mismo objetivo que en Linux, otro terreno: pasar de un usuario normal a SYSTEM o Administrator. Windows tiene sus propias grietas típicas.

2. Privilegios de token

El uniforme prestadoCuando un cliente se conecta a un servicio (por ejemplo, la web o la base de datos), le “entrega” temporalmente una acreditación. Una cuenta con SeImpersonatePrivilege puede ponerse esa acreditación. Si consigues que una acreditación de SYSTEM pase por ahí, te pones su uniforme.
PrivilegioCómo se aprovecha (concepto)
SeImpersonatePrivilege / SeAssignPrimaryTokenFamilia de técnicas “Potato”: fuerzan a que una acreditación de SYSTEM llegue al proceso y la suplantan. Típico en cuentas de servicio (IIS, MSSQL)
SeBackupPrivilege“Leer todo para copias”: permite copiar los archivos SAM y SYSTEM y extraer hashes offline
SeRestorePrivilegeEscribir en cualquier archivo: sustituir un binario del sistema
SeDebugPrivilegeVolcar la memoria de procesos (credenciales)
SeTakeOwnershipPrivilegeApropiarse de archivos protegidos
Muy rentableComo muchos accesos iniciales en Windows caen sobre cuentas de servicio (web, SQL), encontrarte SeImpersonate es habitual. Reconócelo en whoami /priv y es una de las vías más directas a SYSTEM del examen.

Fácil Primer comando

¿Qué comando te dice de golpe tu usuario, grupos y privilegios?

Solución: whoami /all (o whoami /priv solo para privilegios).

Media Detecta unquoted path 
BINARY_PATH_NAME : C:\Program Files\My App\service agent\agent.exe

¿Por qué es peligroso y dónde intentarías colocar un ejecutable?

Solución: la ruta tiene espacios y no está entre comillas. Windows intentará ejecutar, por orden, C:\Program.exe, C:\Program Files\My.exe, C:\Program Files\My App\service.exe… Si tienes permiso de escritura en alguna de esas carpetas (p. ej. C:\Program Files\My App\), colocas ahí service.exe y, al reiniciar el servicio como SYSTEM, se ejecuta el tuyo. Mitigación: poner comillas en el binPath.

Media SeImpersonate

Has accedido como la cuenta del servidor web IIS y whoami /priv muestra SeImpersonatePrivilege Enabled. Describe el plan.

Solución: es el escenario ideal para la familia “Potato”. El plan: subir la herramienta correspondiente, ejecutarla para suplantar una acreditación de SYSTEM y lanzar un comando (por ejemplo, una reverse shell) como SYSTEM. Verifica con whoami que el nuevo proceso es nt authority\system y captura la pantalla. Documenta la versión de Windows, porque la técnica concreta depende de ella.

Reto Encadena el acceso

Entras como usuario normal. WinPEAS marca en rojo: historial de PowerShell con una línea net use X: \\srv\datos /user:admin Verano2024! y el servicio “UpdaterSvc” con binario editable que corre como LocalSystem. ¿Qué camino eliges y por qué?

Solución: hay dos vías. (1) La credencial admin:Verano2024!: pruébala con runas, RDP o WinRM; si admin es administrador local, ya tienes privilegios. (2) El servicio con binario editable: reemplazas el .exe por uno tuyo y reinicias el servicio para obtener SYSTEM. Normalmente se prueba primero la credencial (más limpio y estable) y se deja el servicio como alternativa. Documenta ambas en el reporte como hallazgos independientes.
