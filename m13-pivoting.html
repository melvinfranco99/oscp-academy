Pivoting y túneles

A veces, desde tu Kali no ves todas las máquinas: hay una red “detrás” a la que solo llega el equipo que acabas de comprometer. El pivoting es usar ese equipo como puente.

En este módulo
  1. El problema de la red oculta
  2. Descubrir la red interna
  3. Port forwarding con SSH
  4. Proxy dinámico (SOCKS) y proxychains
  5. Herramientas: chisel, ligolo-ng
  6. Prácticas y cuestionario

1. El problema de la red oculta

El edificio con dos plantasEntras en recepción (planta baja), pero el ascensor a la planta de arriba solo funciona desde un despacho concreto de la baja. Si tomas ese despacho, puedes usar su ascensor para subir. El equipo comprometido es ese despacho; su segunda tarjeta de red es el ascensor.

La máquina “pivote” tiene dos tarjetas de red: una en tu red (la ves) y otra en la red interna (no la ves). Vas a hacer que tu tráfico viaje a través de ella.

2. Descubrir la red interna

Una vez dentro del pivote, busca la segunda red:

# Linux
ip a; ip route; arp -a
# Windows
ipconfig /all; route print; arp -a

Si ves una interfaz con otra IP (p. ej. 10.10.10.5), ahí hay una red nueva. Haz un barrido rápido desde el pivote para ver qué equipos viven (con herramientas que ya estén o un mini script, para no subir nmap si no hace falta).

3. Port forwarding con SSH

Si el pivote es Linux y tienes credenciales SSH, es la forma más sencilla.

TipoComando (desde Kali)Qué consigue
Local (-L)ssh -L 8080:10.10.10.20:80 user@PIVOTETu localhost:8080 llega al puerto 80 de 10.10.10.20
Dinámico (-D)ssh -D 1080 user@PIVOTEUn proxy SOCKS en localhost:1080 que da acceso a TODA la red interna
Local port forward“Conecta mi puerto X con ese puerto concreto de allá”. Útil cuando solo quieres llegar a un servicio (p. ej. una web interna o una base de datos).

4. Proxy dinámico (SOCKS) y proxychains

Proxy SOCKS + proxychainsEl reenvío dinámico (-D) crea un “proxy” por el que puede pasar cualquier conexión hacia la red interna. proxychains es una herramienta que obliga a otros programas (nmap, netexec, el navegador) a pasar por ese proxy.

  1. Levanta el proxy dinámico: ssh -D 1080 user@PIVOTE.
  2. Edita /etc/proxychains4.conf y pon al final socks5 127.0.0.1 1080.
  3. Usa tus herramientas con proxychains delante: 
    proxychains nmap -sT -Pn -p 80,445 10.10.10.20
proxychains netexec smb 10.10.10.0/24 -u user -p pass
proxychains firefox
LimitacionesA través de un proxy SOCKS solo pasa TCP, y debes usar -sT (connect) en nmap, nunca -sS. El ICMP (ping) y el UDP no pasan. Es más lento, así que escanea pocos puertos.

En el examenEl pivoting aparece sobre todo en la parte de Active Directory (las máquinas internas del dominio pueden no ser visibles directamente). Practica un método hasta dominarlo (ligolo-ng o chisel) en vez de saber cuatro a medias.

Prácticas

Dónde practicarTryHackMe “Wreath” (red con pivoting) y salas de “Tunnelling”; HTB “ProLabs” y máquinas con doble red. Monta un mini laboratorio con 3 VMs y dos redes en VirtualBox.
Fácil ¿Hay red interna?

En el pivote, ip a muestra eth0: 192.168.50.10 y eth1: 172.16.8.5. ¿Qué deduces?

Solución: hay una segunda red 172.16.8.0/24 a la que tu Kali probablemente no llega. Es candidata a pivoting.

Media Llega a una web interna

Quieres abrir en tu navegador la web del puerto 80 de 172.16.8.20, al que solo llega el pivote (tienes SSH). Escribe el comando y la URL.

ssh -L 8000:172.16.8.20:80 user@192.168.50.10
# luego en el navegador:  http://127.0.0.1:8000
Media Escanea la red interna

Con un proxy dinámico ya montado en 127.0.0.1:1080, escribe el nmap correcto para escanear puertos comunes de 172.16.8.20.

proxychains nmap -sT -Pn -p 21,22,80,139,445,3389 172.16.8.20

-sT y -Pn obligatorios a través de SOCKS; pocos puertos porque es lento.

Reto Diseña el pivot doble

Comprometes web01 (tiene red con una segunda subred donde vive SRV02). Desde SRV02 hay aún otra subred con el DC. ¿Cómo lo montarías conceptualmente?

Solución: pivoting “en cadena” (doble salto). Con ligolo-ng montas un agente en web01 y expones la subred de SRV02 a Kali; comprometes SRV02 y montas un segundo agente/relé que exponga la subred del DC. Con SSH sería encadenar reenvíos (-D a través del primer proxy con proxychains). La idea clave: cada máquina comprometida extiende tu alcance a la siguiente red. Documenta la topología con un diagrama en el reporte: ayuda muchísimo a quien lo lee.
